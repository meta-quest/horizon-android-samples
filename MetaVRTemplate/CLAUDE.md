# Meta VR Template

A starter 2D panel app for mixed reality, generated by the Meta VR Android Studio Plugin's New
Project wizard. Single-activity Compose: all UI lives in
`app/src/main/java/.../metavrtemplate/MainActivity.kt`.

## Build & Deploy

**Prerequisites:** JDK 17, Android Studio (Meerkat+), Meta Spatial Simulator or Quest device.

```bash
./gradlew assembleDebug    # Build debug APK
./gradlew installDebug     # Install and run on connected device/simulator
```

Dependencies are declared in `gradle/libs.versions.toml`. The Meta VR UI Set SDK
(`com.meta.metavrx.uiset:uiset-compose-compat`) supplies the theme, components and icons below.
It is declared without a version: the `com.meta.metavrx:metavrx-bom` platform, set by the
`metavrxBom` variable, selects it.

## Meta VR UI Set SDK Theming

This template uses the Meta VR UI Set SDK, package `metavrx.uiset.compose`. Key patterns:

### Dark Theme Setup
```kotlin
UiSetTheme(colorScheme = darkColorScheme()) {
  // App content here
}
```
- `UiSetTheme.colorScheme.background.container.brush` — gradient brush for the panel background
- `UiSetTheme.colorScheme.background.content.primary` / `.secondary` — text on the panel background
- `LocalContentColors.current.primary` / `.secondary` — text inside a card, which provides its own content colors

### Components
`SideNavItem` (icon, label, selected state), `SecondaryCard` (rounded content card), `Text`,
`Icon` and `Icons.Regular.*`, plus `UiSetTheme.typography.*` and `UiSetTheme.shapes.*`.

### Pitfalls
- **Paint the panel background.** Apply `UiSetTheme.colorScheme.background.container.brush` to the root layout.
- **Use the UI Set `Text` and `Icon`** from `metavrx.uiset.compose`, not the Material 3 ones, and pass the content color of the surface they sit on.
- **Icons are composable getters.** `Icons.Regular.*` can only be read during composition, not in a top-level `val` or an enum constructor.

## Manifest Configuration

Read `app/src/main/AndroidManifest.xml` for the OS configuration: the
`metavr:uses-metavr-sdk` element, the legacy `horizonos:uses-horizonos-sdk` declared alongside it,
`com.oculus.supportedDevices`, and the panel's default `<layout>` size. What the values mean:

- `metavr:` namespace: `http://schemas.meta.com/metavr-sdk`; legacy `horizonos:` namespace: `http://schemas.horizonos/sdk`
- `metavr:minSdkVersion` is the oldest installable OS release.
- `metavr:targetSdkVersion` opts into behavior through that OS release
  and should advance independently of the minimum.
- Meta VR SDK levels are separate from Android's `minSdk` and `targetSdk`.

## Look and Pinch

Look and pinch is the **default input method on devices that ship without controllers**, so these
are requirements, not preferences. Two OS facts drive all of them:

- **The app receives no hover events.** Raw eye-tracking data is never exposed to panel apps.
  Pointer events behave like touch, so anything depending on hover state will not work.
- **The app never receives the user's gaze.** The *system* draws the hover and selection
  affordance from its own "UI Understanding" of the panel. An element it does not recognise as
  interactive gets no affordance even though it responds to a pinch, so the user cannot tell it
  is targetable.

Rules:

| Rule | How it is done here |
|---|---|
| Interactive targets are at least 48dp, 60dp recommended | `LookAndPinchMinTargetHeight` is applied to every side-nav item |
| Make interactivity visible to the system | Use `Modifier.clickable`, or a component that takes an `onClick`. Do not draw a bare `Canvas` and handle raw pointer input |
| Never put a click listener on static content | A stray `Modifier.clickable` makes the system highlight content the user cannot act on |
| Group cards as one target | Put the click listener on the parent container, never on the children, or each child highlights separately |
| Declare the shape before the click | Put `Modifier.clip(shape)` before `clickable`, or give both the same shape — otherwise the system highlights the rectangular bounds |
| Do not style `state_hovered` | Look and pinch never delivers hover events. Style pressed and selected instead |

The system infers a composable's real shape only on **Jetpack Compose 1.10.0 or newer**; older
versions fall back to rectangular bounds. This template resolves 1.11.0.

Native tooltips never appear under look and pinch; a tooltip carrying real meaning needs the Gaze
SDK, which this template does not depend on.

## Platform Constraints

Not available on the OS: Google Mobile Services (Auth, Location, Ads, Billing), Google
Play Billing, the Android Notification API, and camera access. Use Android-native alternatives
where available (e.g. `LocationManager` instead of GMS Location).
